一、业务背景与痛点（合并）

  1. 时效无数据：补贴审核要求新接收流程 10 天内闭环，由特定人全权负责并关联月底绩效，但系统无时效提醒、无超时标记，考核无数据支撑（R16）。
  2. 筛选不足以统计：补贴审核量大，现有筛选维度无法按审核人、大区、部门做绩效统计与分流查询（R17）。
  3. 驳回不可追溯：无法统计整体被驳回多少次、按口径拆分（设计/预结算/其他），也无法查询每轮申报的版本文件，返工分析缺数据（R18）；审核时只能人工翻两份文件对比本轮调整了什么，效率低且易漏（R19）。
  4. 关键信息藏得深：招牌面积的明细（组成部分、规格、面积拆分）藏在弹窗里，审核需逐个点开（R20）。
  5. 流程角色不清、被非关键节点阻塞：补贴流程要流转到招商复核，但未显示审核人/复审人角色分工，且前序流程不应被招商节点阻塞（R21）。
  6. 工作量统计缺口径：档案更新中涉及补贴的部分在档案流程里直接审批完，补贴审核月度工作量无法体现（R22）。

三、功能需求详述（R16–R22）

R16 工程补贴审核 10 天闭环时效提醒与导出

  1. 时效规则（审核类型 = 工程补贴审核）：
    • 进入待办后第 7 天未闭环 → 标记「即将超时」（橙色标签）；
    • 超过 10 天未闭环 → 标记「已超时」（红色标签 + 超时时长展示）；
    • 时效起算点 = 补贴审核流程接收时间（流程进入当前审核人待办的时刻，取 BPM 审批记录 approvalTime，落库为补贴审核单新字段 receive_time）；闭环点 = 流程审核完成 / 驳回终态时间（close_time；R21 落地后招商复审非阻塞，close_time 以审核人通过时间为准）。
  2. 提醒动作：第 7 天触发一次提醒（APP 待办角标——复用 /engineer/audit/benefit 待办数据源叠加时效标识 + PC 待办「即将超时」样式）；第 10 天触发超时提醒并抄送工程督察组负责人。
  3. 列表展示：审核列表补贴类记录新增「剩余时效 / 超时时长」列（服务端按自然日计算下发）；状态页签在现有 4 态基础上增加「即将超时」「已超时」快捷筛选（仅补贴类型生效，计数并入 statistics 接口）。
  4. 导出：AUDIT_EXPORT 导出配置新增「接收时间、闭环时间、耗时天数、时效状态（正常/即将超时/已超时）」4 个字段，支撑月底绩效核算。
  5. 口径：节假日不顺延（自然日）；流程中途被取消（CANCEL）不计时效。

R17 工程补贴审核筛选维度扩展

  1. 新增筛选项（4 项）：
    • 审核人（督察）：人员选择器，取补贴审核流程中「审核人」角色（内部稽核/首审节点）的实际处理人（BPM 审批记录），替代现状恒空的 auditorName；
    • 大区：复用系统大区设置枚举（与项目所属大区一致）；
    • 部门维度：按审核流程参与人所属部门（工程督察/招商等组织架构）多选；
    • 流程审核完成时间：日期区间（起 - 止），取 close_time 终态时刻。
  2. 列联动：列表新增「所属大区」「审核人（督察）」列；导出文件同步新增 4 项筛选对应字段。
  3. 组合查询：新增筛选与现有 10 项筛选任意叠加（AND 关系），兼容 onlyYou 开关。

R18 工程补贴审核：驳回次数统计与版本文件查询

  1. 驳回次数统计：补贴详情页新增「驳回记录」区块：
    • 汇总：累计驳回 N 次；
    • 分口径：按申报数据类型拆分（设计数据 X 次、预结算数据 Y 次、其他口径 Z 次，分类枚举可配置；口径映射取驳回时选择的驳回节点——工程设计/项目验收/工程结算）；
    • 明细列表：每次驳回的时间、驳回环节、驳回人、驳回原因（数据源 = BPM 审批记录解析结构化落库，不再只依赖时间线渲染）。
  2. 版本文件查询：补贴详情新增「版本文件」TAB——每轮申报对应一个版本（V1、V2…），每版本可查看/下载该轮提交的完整文件包（六类材料文件按版本快照留存，驳回附件按 workItemId 归入对应版本）；版本与驳回记录一一关联（驳回后重新提交生成新版本）。
  3. 列表联动：审核列表新增「累计驳回次数」列；导出同步。
  4. 统计口径：同一流程内「驳回 → 重新提交」计一轮；流程级重新发起（R22 拆出的新补贴流程）不计入本流程驳回次数。

R19 工程补贴审核：新旧申报数据对比展示

  1. 对比视图：补贴审核详情新增「新旧对比」视图（与补贴信息/版本文件并列）：左侧上一版本申报数据、右侧当前版本，逐字段对齐展示（复用 co-diff-table 组件）。
  2. 差异高亮：发生变化的字段（金额、面积、数量、清单项增减等）高亮标注变更（旧值 → 新值），新增项标绿、删除项标红、修改项标橙；文件字段支持新旧文件对照。
  3. 变更摘要：视图顶部生成变更摘要（变更字段数、金额合计差异 = 新 − 旧），审核人可一键确认「已核对差异」（确认动作随审批意见留痕到 BPM）。
  4. 入口条件：首轮申报（无上一版本）不显示对比视图，提示「首轮申报无对比数据」。
  5. 权限：审核人、复审人、工程督察组可查看；提交人不可见（防逆向凑数）。

R20 工程补贴审核：招牌面积明细前置展示

  1. 详情页直出：「招牌面积」汇总值下方直接展开明细表（明细项名称、规格/尺寸、数量、小计面积），无需二次点击；取数统一改由补贴详情接口输出（SETTLEMENT_INFO 版明细，与汇总值同源同口径，消除补贴卡与结算弹窗双数据源不一致）。异形招牌显「面积 m²」、普通招牌显「长 m × 宽 m」（沿用现有 formatSize 口径）。
  2. 合计校验：明细小计之和与汇总值实时校验，不一致时红色提示「明细合计与汇总不符」，提交审核时拦截。
  3. 可折叠：明细区支持折叠/展开记忆（默认展开）；导出补贴审核数据时同步输出明细行。

R21 工程补贴审核：任务节点角色显示 + 招商复审不阻塞主流程

  1. 节点角色显示：补贴审核详情的当前任务节点区域显示：审核人：综合稽核（督察）、复审人：督察 / 招商人员，随流程当前所处环节高亮对应角色（已完成=绿、当前=蓝、未开始=灰）。
  2. 流程编排：
    • 审核人（综合稽核-督察）通过后，流程自动流转到招商（复审人：招商人员；BPM 模板 gong_cheng_bu_tie 增加招商复审节点）；
    • 招商复审为非阻塞节点：复审结论（通过/存疑）不改变整体流程进度，流程完成时间（close_time）以审核人通过时间为准；
    • 复审驳回仅产生「复审意见」记录并通知审核人，不回退主流程状态。
  3. 系统对接：复审节点与招商系统对接（复审人身份、复审动作回传），对接失败时复审在工程系统内兜底完成，不阻塞流程。
  4. 列表联动：「复审人」列展示当前复审人（招商人员），复审状态在「当前任务状态」中体现为「复审中（不阻塞）」；补贴行审核人列同步输出初审实际处理人。

R22 档案更新关联补贴：单独发起补贴审核流程

  1. 拆分规则：档案更新提交时，系统识别本次更新中「涉及补贴金额/补贴项」的内容（复用现有 isRelatedAllowance 判定口径：新店/迁址 + 开间/拐角/营业面积/招牌信息变更）：
    • 涉及补贴 → 自动新发起一条独立的补贴审核流程（审核类型：工程补贴审核-档案更新，audited_type 新枚举值），原档案更新流程继续走档案审批本身；
    • 不涉及补贴 → 维持现状，不生成新流程。
  2. 关联关系：新补贴流程与源档案更新流程双向关联（详情页互跳链接 + 源单号字段），审计可追溯。
  3. 审核口径：新流程享受 R16 时效（10 天闭环）、R17 筛选、R18 驳回统计等全部补贴审核能力；绩效统计（月度补贴审核工作量）按「独立流程数」计数。
  4. 存量：上线前已在档案更新流程中审批完的关联补贴不回溯拆分；上线后存量进行中的档案更新，在下次提交涉及补贴内容时触发拆分。
